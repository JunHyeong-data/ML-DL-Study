## 1. Image Classification이란?

**컴퓨터 비전 = 기계에게 사람과 같은 "눈"을 달아주는 것.**
단순한 광학적 인식이 아니라, 시신경 → 뇌의 시각 정보 처리까지 포함하는 개념 (인지, 이해, 대응까지).

**Image Classification Task**: 이미지를 입력받아 정해진 클래스 중 하나(또는 여러 개)로 분류하는 문제.

- 사람: 소수의 카테고리로 분류
- 컴퓨터: 보통 1,000개 클래스 (ImageNet 기준), 대규모 시스템은 10만~100만 개 클래스까지 사용

### 문제 정의 시 고려할 점
사진 속에 물체가 반드시 하나만 있다는 보장이 없음 → 아래와 같은 설계 선택지가 존재:

- **Single-label vs Multi-label**: 하나만 맞히면 되는지, 존재하는 모든 오브젝트를 다 찾아야 하는지
- **없는 클래스 처리**: "모른다"고 할지, "없다"고 할지, 새로운 라벨로 취급할지
- 이 수업에서는 기본적으로 **이미지 하나당 대표(main) 오브젝트 하나를 맞히는 문제**로 단순화하여 다룸

## 2. 컴퓨터가 이미지를 보는 방식

사람 눈에는 하나의 장면으로 보이지만, 컴퓨터에게 이미지는 **숫자들의 배열**일 뿐임.

- 각 픽셀은 RGB 3개 채널의 정수값 (0~255)으로 색을 표현
- 이미지는 결국 **3차원 텐서**로 표현됨:

$$\text{Height} \times \text{Width} \times 3 (\text{RGB Channels})$$

예: 32×32 크기의 저해상도 이미지라면

$$32 \times 32 \times 3 = 3072$$

개의 숫자로 표현되는 벡터로 볼 수 있음.

## 3. Image Classification이 어려운 이유 (Challenges)

| Challenge | 설명 |
|---|---|
| **Scale variation** | 같은 물체라도 사진 속 크기가 다양함 (부분만 나오거나 전체가 나오거나) |
| **Viewpoint variation** | 3차원 물체를 2차원으로 투영하는 과정에서 촬영 각도에 따라 보이는 형태가 달라짐. 카메라를 아주 살짝만 돌려도 사람 눈에는 정보량이 거의 같아 보이지만, 픽셀 값들은 크게 바뀜 → 같은 대상임을 인식시키는 것이 큰 챌린지 |
| **Background clutter** | 배경과 비슷한 색/질감으로 위장된 물체 (camouflage) → 컴퓨터 비전은 원래 위장된 적을 찾아내려는 군사적 목적(분사 기술)에서 출발했다는 역사적 배경 |
| **Illumination** | 조명(낮/밤)에 따라 색상이 크게 달라짐. 자율주행처럼 낮 데이터 위주로 학습했을 때 야간 대응이 어려운 문제와 직결 |
| **Occlusion** | 다른 물체에 가려 일부만 보이는 경우 (예: 풀숲에 얼굴만 내민 고양이) |
| **Deformation** | Rigid body(책상처럼 형태 고정)와 달리 사람처럼 다양한 자세(pose)를 취할 수 있는 물체는 형태 변화가 큼 |
| **Intraclass variation** | 같은 클래스 안에서도 색상, 형태 등 세부 차이가 존재. 클래스의 정의(무엇을 같은 클래스로 볼 것인가) 자체가 사람이 정하는 설계의 영역임 |

> 클래스 정의 예시: "자동차"라는 클래스를 만들 때 — 색상은 무시, 지붕 유무는 무시(컨버터블 포함), 바퀴 개수(이륜차 포함 여부) 등은 명확히 정의해야 모델이 무엇을 무시하고 무엇을 봐야 하는지 학습 가능

**Rule-based 접근의 한계**: 초기에는 edge detection(픽셀 간 밝기 차이로 윤곽 추출) 후 "귀 모양", "수염" 같은 특징을 사람이 직접 규칙으로 짜려는 시도가 있었으나 대부분 실패함.

## 4. Data-Driven Approach (머신러닝 방식)

머신러닝은 **데이터로부터 패턴을 발견**하여 classification/regression 등을 수행하는 data-driven AI.

### 절차
1. 이미지(input)를 대량 수집
2. 각 이미지에 대한 정답(label) 수집
3. 이 (image, label) 쌍으로 **모델 학습** → 패턴을 배운 함수(모델) 생성
4. 학습이 끝난 모델에 **처음 보는 이미지**를 넣어 예측(inference) 수행

즉, 머신러닝에서 우리가 만들어야 할 함수는 크게 두 가지:
- **Train function**: (이미지, 정답) → 모델
- **Predict function**: (모델, 새 이미지) → 예측 라벨

## 5. Linear Classifier

### 5.1 Parametric Approach

배우고자 하는 함수:

$$f(x, W) = \text{score}$$

- $x$: 이미지 (input, 3072차원 벡터로 flatten됨)
- $W$: 학습 가능한 파라미터 (weight)
- 출력: 클래스별 **score** (확정적 라벨이 아니라 "고양이일 가능성 85%" 식의 점수)

Score는 사람이 threshold를 정해 활용 (예: Google Photos에서 "고양이" 검색 시 특정 score 이상인 이미지만 노출)

### 5.2 Score Function 정의

가장 단순한 관계 가정: **선형 관계(Linear relationship)**

$$f(x, W) = Wx$$

이는 중학교 때 배운 일차함수 $y = ax$ 의 벡터/행렬 버전.

### 5.3 Dimension 맞추기 (CIFAR-10 예시)

- 이미지 크기: 32 × 32 × 3 = 3072차원 벡터 → $x$: (3072, 1)
- 클래스 개수: 10개 → 출력 $y$: (10, 1)

따라서:

$$W: (10, 3072), \quad x: (3072, 1) \Rightarrow Wx: (10, 1)$$

- $W$의 행(10개) = 클래스 개수
- $W$의 열(3072개) = 입력 픽셀 개수
- $W$의 각 원소는 "해당 픽셀 값이 해당 클래스 score에 얼마나 (양/음으로) 기여하는지"를 의미

### 5.4 Bias Term

$$f(x, W) = Wx + b$$

- $b$: (10, 1) 벡터, 클래스마다 하나씩
- $x$와 무관하게 항상 더해지는 값 → 데이터 자체의 클래스 불균형(prior)을 반영
  - 예: 학습 데이터의 90%가 고양이라면, 잘 모를 때 일단 고양이 쪽으로 점수를 높여주는 역할
  - 데이터가 균등하면 bias는 0에 가깝게 학습됨

### 5.5 Bias Trick

매번 $+b$를 따로 다루는 번거로움을 없애기 위해:

- $W$ 뒤에 $b$를 한 열 추가 → $W' = [W, b]$, shape (10, 3073)
- $x$ 뒤에 1을 추가 → $x' = [x, 1]$, shape (3073, 1)

$$f(x, W) = W'x' = Wx + b$$

이후로는 편의상 **$y = Wx$ 안에 항상 bias가 내부적으로 포함되어 있다**고 표기 (숙제에서도 bias는 명시 안 되어 있어도 항상 있어야 함).

### 5.6 왜 Parametric Model인가

- $W$: 학습 가능한(learnable) 파라미터 — 우리가 결정하는 값
- $x$: 외부에서 주어지는 입력 — 통제 불가
- 학습 완료 후에는 학습 데이터를 더 이상 참조할 필요 없이 $W$만 있으면 됨
  → **메모리 효율적**, 추론 시 행렬 연산 한 번으로 **빠름**
  → k-NN처럼 매번 전체 학습 데이터와 비교할 필요 없음 (k-NN: train 데이터 크기만큼 비교 필요, Linear Classifier: 클래스 개수만큼만 계산)

## 6. Linear Classifier의 세 가지 해석 관점

### 6.1 Algebraic viewpoint (대수적 관점)

각 클래스의 weight row는 픽셀별 가중치이며, 입력 이미지와 element-wise 곱 후 합산 → score.
- 특정 픽셀 위치의 weight가 크면: 그 위치의 픽셀값이 클수록 해당 클래스일 가능성 ↑
- weight가 0이면: 해당 픽셀은 무관
- weight가 큰 음수면: 픽셀값이 작을수록 해당 클래스일 가능성 ↑

### 6.2 Geometric viewpoint (기하학적 관점)

입력이 2차원($x_1, x_2$)이라 가정하면 각 클래스의 score function은 하나의 **평면(hyperplane)**으로 그려짐.

- $W$의 각 성분 = 그 축 방향의 기울기(slope)
- $b$ = 평면 전체를 위아래로 이동
- 여러 클래스의 평면을 위에서 내려다봤을 때, 특정 지점에서 **가장 높은 색(=가장 높은 score)**을 가진 클래스로 분류
- 선형 모델이므로 클래스 간 **decision boundary는 반드시 직선(고차원에서는 초평면)** 형태로만 나타남

**Threshold(수면) 개념**: 무조건 최고 점수 클래스로 배정하지 않고, 특정 score 이상일 때만 해당 클래스로 인정 (예: "비행기"라 부르려면 일정 score 이상이어야 함). Threshold를 어떻게 정할지는 실험적으로 결정.

### 6.3 Visual/Template viewpoint (템플릿 매칭 관점)

학습된 $W$의 각 클래스 row를 다시 이미지 크기(32×32×3)로 reshape하면, 시각화 가능.

- 학습이 끝나면 각 클래스에 대해 **평균적인 템플릿 이미지**처럼 보이는 패턴이 나타남
  - 예: "말" 클래스 템플릿은 초원+하늘 배경에 좌우 어느 한쪽을 보는 모습이 섞여서 나타남
  - "자동차" 클래스는 특정 색 계열, 정면 각도가 많으면 그 특징이 두드러짐
  - 형태가 다양한 클래스(새, 강아지 등)는 템플릿이 뚜렷하지 않고 뭉개져 보임
- **해석**: 학습 = 클래스별로 "한 장의 템플릿"을 배우는 것. 추론 = 새 이미지가 어느 템플릿과 가장 잘 매칭되는지 계산하는 것
- k-NN과 유사한 아이디어지만, k-NN은 학습 데이터 전체와 비교(느림), Linear Classifier는 클래스 개수만큼의 템플릿과만 비교(빠름)

## 7. Score를 확률로 변환하기

Score 값 자체(예: -96.8, 437.9)는 크기 비교는 되지만 **"얼마나 확신하는지"에 대한 직관이 없음** → 확률(0~1)로 변환 필요.

### 7.1 이진 분류 (Binary): Sigmoid

두 클래스 score를 $s_1, s_2$라 하고 $s = s_1 - s_2$로 정의.
원하는 함수의 조건:
- $s$가 클수록(양의 방향으로 크면) → 1에 가까운 값
- $s$가 작을수록(음의 방향으로 크면) → 0에 가까운 값
- $s = 0$ → 0.5 (50:50)

이 조건을 만족하는 함수가 **Sigmoid function**:

$$\sigma(s) = \frac{1}{1 + 2^{-s}}$$

$s = s_1 - s_2$를 대입하면:

$$P(\text{class 1}) = \sigma(s_1 - s_2) = \frac{2^{s_1}}{2^{s_1} + 2^{s_2}}$$

$$P(\text{class 2}) = \sigma(s_2 - s_1) = \frac{2^{s_2}}{2^{s_1} + 2^{s_2}}$$

**확률 조건 검증**
1. 모든 값이 0~1 사이: 지수함수는 항상 양수이므로 분모가 분자보다 항상 크거나 같음 → 0~1 사이 보장
2. 전체 합이 1: 두 식을 더하면 분모가 같아져서 합이 1이 됨 → 수학적으로 확률 조건 충족

### 7.2 다중 클래스: Softmax

클래스가 3개 이상일 때는 sigmoid를 일반화한 **Softmax**:

$$P(y = k \mid x) = \frac{e^{s_k}}{\sum_{j} e^{s_j}}$$

- 모든 score에 exponential을 씌운 뒤, 자기 자신 / 전체 합으로 정규화
- 합이 1, 각 값이 0~1 사이 → 확률 조건 만족

### 7.3 Calibration 이슈 (중요 개념)

Softmax/Sigmoid 출력이 수학적으로 "확률"의 조건은 만족하지만, **실제 통계적 확률과 일치한다는 보장은 없음**.

- 모델이 "85%"라고 말했다고 해서, 그런 예측을 850장 모았을 때 실제로 850장이 맞다는 보장이 없음
- 모델이 낸 확률이 실제 빈도와 얼마나 일치하는지를 "**Calibration**"이라 부르며, 별도의 연구 분야가 존재
- 확실히 말할 수 있는 것은 "85% 예측이 95% 예측보다 더 확신도가 낮다" 정도의 **상대적 순서**뿐

## 8. Loss Function

### 8.1 정의

Loss function: (예측, 정답)을 입력받아 **얼마나 틀렸는지를 점수(감점)로 환산**하는 함수.
- 맞았으면 0
- 조금 틀리면 작은 값
- 많이 틀리면 큰 값

"Loss(손실)"이라 부르는 이유: 만점 채점이 아니라 **감점 방식**으로 계산하기 때문.

### 8.2 Cross-Entropy Loss

$$L = -\frac{1}{N}\sum_{i}\sum_{k} y_{ik} \log(\hat{y}_{ik})$$

- $y_{ik}$: $i$번째 이미지의 $k$번째 클래스 정답 (one-hot: 정답 클래스만 1, 나머지 0)
- $\hat{y}_{ik}$: 모델이 예측한 확률

**정답만 남는 형태로 단순화**: 정답 클래스 인덱스를 $t_i$라 하면, one-hot이므로 $k = t_i$일 때만 항이 살아남음:

$$L = -\frac{1}{N}\sum_{i} \log(\hat{y}_{i, t_i})$$

즉, **"정답 클래스에 대해 모델이 준 확률"에 마이너스 로그를 취해 평균낸 것**.

**왜 이 형태가 loss로 적합한가**:
- $-\log(p)$ 함수는 $p$가 1에 가까울수록(정답을 잘 맞출수록) 0에 가까운 값, $p$가 0에 가까울수록(많이 틀릴수록) 매우 큰 값을 반환
- 정확히 우리가 원하는 "잘 맞으면 낮은 loss, 틀리면 높은 loss"의 형태와 일치

### 8.3 KL Divergence

두 확률분포 $p, q$ 사이의 차이를 측정하는 또 다른 방법:
- 두 분포가 같으면 0, 다를수록 큰 값
- 단, **거리(distance)는 아님** — $p \to q$와 $q \to p$의 값이 다름 (비대칭), 삼각부등식도 만족하지 않음
- 그래도 "정답 분포와 예측 분포를 가깝게 만든다"는 목적에 실용적으로 잘 작동하여 널리 사용됨

## 9. Optimization (최적화)

### 9.1 개념

Optimization: 주어진 criteria(기준)를 최대/최소로 만드는 최적의 값을 찾는 것.
여기서는 **Loss function을 최소화하는 $W$를 찾는 것**이 목표.

### 9.2 Gradient Descent (경사하강법)

비유: 눈을 가리고 산에서 가장 낮은 곳을 찾아 내려가는 것.
- 현재 위치에서 가장 가파르게 내려가는 방향(gradient)을 계산
- 그 반대 방향(내려가는 방향)으로 한 걸음씩 이동

업데이트 규칙:

$$W \leftarrow W - \alpha \cdot \nabla_W L$$

- $\nabla_W L$: 현재 $W$에서의 gradient (기울기)
- 기울기가 양수 → 최적점이 더 왼쪽에 있음 → $W$를 줄여야 함 (그래서 마이너스 부호)
- 기울기가 음수 → $W$를 키워야 함
- $\alpha$: **learning rate** — 한 걸음의 보폭 크기 (상수)
- 종료 조건: gradient가 거의 0에 수렴 → local minimum 도달

### 9.3 한계점

| 한계 | 설명 |
|---|---|
| **Saddle point** | 한쪽 축으로는 극대, 다른 축으로는 극소인 지점. gradient가 0이 나와 "다 내려왔다"고 잘못 판단할 수 있음. 저차원에서는 드물지만 고차원으로 갈수록 매우 빈번해짐 |
| **미분 불가능성** | 대상 함수가 미분 불가능한 점(불연속점 등)을 가지면 gradient descent 적용 불가 (예: classification accuracy처럼 이산적인 지표) |
| **속도 문제** | 전체 학습 데이터를 다 풀어보고 채점해서 업데이트 방향을 정하는 것은 데이터가 커질수록 매우 느림 |

### 9.4 Mini-batch (Stochastic Gradient Descent)

전체 데이터 대신 일부(mini-batch)만 뽑아 "모의고사"처럼 풀어보고 그 결과로 업데이트.

- Batch size가 클수록: gradient 추정 정확도 ↑, 그러나 계산 시간 ↑ (메모리 한계도 고려해야 함)
- Batch size는 문제/데이터 특성에 따라 다름 (이미지: 수천~수만, 비디오: 몇 개 수준으로 작아지기도 함)
- Mini-batch를 쓰면 gradient가 noisy해짐 → 학습 곡선(loss curve)이 들쭉날쭉하게 나타나는 이유:
  1. 특정 배치에 맞춰 업데이트했지만 전체적으로는 오히려 성능이 떨어질 수 있음
  2. 그래프에 찍히는 loss 값 자체도 해당 mini-batch에 대해서만 계산된 값이라 노이즈가 있음
  - 전체적인 추세는 우하향(감소)하는 것이 정상

### 9.5 학습 종료 시점 판단

Gradient descent가 단조 감소한다는 보장이 없으므로 "언제 멈출지" 정하기 어려움.
실무적으로 사용하는 방법:
- 일정 기간 동안 loss가 특정 임계치 이상 줄어들지 않으면 종료
- 혹은 사람이 직접 곡선을 보고 경험적으로 iteration 수(예: 100k)를 정해서 학습

## 10. 이번 시간 정리 & 다음 시간 예고

이번 시간에 다룬 파이프라인:

1. **모델 형태 결정**: $f(x, W) = Wx + b$ (Linear Classifier)
2. **$W$ 초기화**: 임의로 설정
3. **Forward**: 데이터를 넣어 예측(score) 계산
4. **채점**: Loss function으로 예측이 정답과 얼마나 다른지 계산 (Cross-Entropy, KL Divergence 등)
5. **업데이트**: Optimization(Gradient Descent 등)으로 $W$를 개선
6. 3~5를 반복하며 수렴할 때까지 학습

> 이는 **Supervised Learning**의 기본 큰 틀임.
