## 0. 지난 시간 복습

### 0.1 비선형 decision boundary를 어떻게 모델링할 것인가

Linear classifier는 선형 변환이므로 비선형 경계를 만들 수 없다. 두 가지 접근:

**(a) 전통적 방법 — 표현(representation) 자체를 바꾸기**
- XY 좌표계가 아닌 다른 좌표계로 보낸다 (예: 극좌표).
- 고차원으로 보내면 linearly separable한 공간이 될 수 있다.
- 그 공간에서 linear classifier를 학습시키면 분류가 가능해진다.

**(b) 뉴럴 네트워크 — activation function이 비선형성을 담당**
- linear mapping → nonlinear activation → 반복.
- 층을 쌓을수록 표현 가능한 함수의 capacity가 커진다.

### 0.2 Sigmoid를 activation으로 쓰면 안 좋은 이유

| 문제 | 설명 |
|---|---|
| **Gradient vanishing** | 입력 절댓값이 커지면 출력이 0 또는 1 근처로 saturate → 미분값이 0에 가까워짐 → backprop이 진행될수록 gradient가 0으로 소멸 → 학습 불가 |
| **Not zero-centered** | 출력이 항상 양수라 gradient가 전부 같은 방향으로만 움직임 → 비효율적 업데이트. 단, batch size를 크게 하면 상쇄되어 큰 문제는 아님 |

### 0.3 ReLU의 문제 — Dead ReLU

- 출력이 음수면 gradient가 무조건 0.
- 한번 죽으면 업데이트가 안 되고, 업데이트가 안 되니 계속 음수가 나와 영원히 죽는다.
- 대응: 초기화를 약간 양수 쪽으로 해서 시작 (완전한 해결은 아니지만 초기부터 죽는 것은 방지).

## 1. Data Augmentation

### 1.1 왜 필요한가 — Labeling cost

- 딥러닝이 2012년경 터진 배경: 2000년대 중후반부터 인터넷으로 데이터가 축적되기 시작.
- 그런데 데이터 하나를 만드는 비용이 크다. 사진을 찍고 → 사람이 레이블링해야 1건이 만들어진다.
- 컴퓨터처럼 초당 수만 건 처리되는 일이 아니다. **레이블링 코스트가 지금도 가장 큰 병목.**
- "인건비 싼 나라에서 처리하자"는 회사 차원의 솔루션이 있지만, 사람이 일하는 속도 자체는 크게 다르지 않다. 1만 개를 2만 개로 늘릴 수는 있어도 100억 개는 못 만든다.

### 1.2 핵심 아이디어

이미지는 픽셀 단위로 저장되지만, **사람이 받아들이는 정보량은 픽셀 레벨 변화와 무관**하다.
1초 전과 지금 강의실 사진은 픽셀 레벨에서는 엄청나게 다르지만, 의미는 똑같다.

> **원칙: semantic이 바뀌지 않는 범위에서, 픽셀 레벨에서는 많은 것이 바뀌게 만든다.**

그리고 **semantic은 풀고자 하는 task에 따라 달라진다.**
- 예: 얼굴 일부를 가린 이미지
  - Face recognition → 여전히 같은 레이블로 쓸 수 있음
  - 장발/단발 분류 → 머리카락과 무관한 부분만 가려졌다면 여전히 유효

즉 **"이 변형을 했을 때 label이 여전히 유효한가?"** 를 매번 판단해야 한다.

### 1.3 대표적인 augmentation 기법

**(a) Horizontal Flip (좌우 반전)**
- 고양이가 왼쪽을 보든 오른쪽을 보든 "고양이"다.
- 세상의 많은 것들이 좌우가 바뀌어도 semantic이 안 바뀌므로 가장 흔히 쓰임.

**(b) Vertical Flip (상하 반전) — 주의**
- 지구 중력 때문에 대부분의 사진은 중력 방향이 아래로 향하게 찍혀 있다.
- 상하 반전은 "실제로 촬영될 수 있는 성격의 사진"이 아닌 경우가 많다 → 조심해서 사용.

**(c) Random Crop**
- 같은 물체여도 전체를 찍을 수도, 부분만 찍을 수도 있다.
- 사람이 알아볼 수 있는 수준이면 모델도 맞출 수 있어야 한다.
- 근거: **Translation Invariance** — 평행 이동에 대해 semantic이 달라지지 않는다.

**(d) Scale / Zoom**
- 줌을 당겨 크게 찍든 작게 찍든, reasonable한 범위 내에서는 알아볼 수 있어야 한다.
- 해상도를 낮춰 전체를 쓰거나, 큰 이미지에서 잘라내 쓰거나.

**(e) Rotation**
- 셀카를 0.01도 각도까지 맞춰 찍지는 않는다 → 1도 정도 회전은 semantic이 안 바뀜.
- 회전 행렬 적용.

**(f) Stretch / Random Erasing 등**
- task에 따라 괜찮을 수도, 아닐 수도 있음. 지나치지 않으면 대체로 무방.

### 1.4 Case Study — ImageNet (ILSVRC)

**데이터셋**
- 100만 장 이미지, 1000개 클래스.
- 100만 장이 많아 보이지만 **클래스당 1000장**뿐. 고양이의 포즈·색깔·크기 온갖 variation을 고려하면 매우 적은 양이다.

**Training time augmentation**
1. 긴 쪽/짧은 쪽 길이가 제각각이므로, **[256, 480] 사이에서 랜덤 값 하나**를 뽑는다.
2. **짧은 쪽**이 그 크기가 되도록 resize.
3. 거기서 **224 × 224 패치를 랜덤하게 crop**.
4. 전체 이미지의 레이블을 그대로 사용.

> 224 × 224는 이 데이터셋의 표준으로 정해진 크기이고, 이후 수많은 연구가 이 크기를 따르게 된다.
> 480을 상한으로 둔 이유: 너무 커지면 224 패치가 전체의 극히 일부만 차지해서 무엇인지 알 수 없게 된다.
> 이 범위면 어떤 크기가 되더라도 한 변의 절반 정도는 차지하게 된다.

**Test time augmentation (다수결)**
- 테스트할 때는 잘라내면 정보 손실이지만, 학습을 224로 했으므로 그 크기로 맞춰야 한다.
- 해결책: **5개 scale × 10개 crop = 50개 예측 후 다수결**
  - 10 crop = 정중앙 1 + 네 귀퉁이 4 = 5개, 그리고 각각의 좌우 반전 5개
  - 50개 중 37개가 "고양이"라고 하면 고양이로 결정
- 당시 ILSVRC는 커리어를 좌우할 만큼 공신력 있는 대회여서, 성능을 최대한 끌어올리기 위한 이런 트릭들이 총동원되었다.

### 1.5 Color Jitter — RGB에서 HSL로

밝기·채도를 조정하는 필터 효과는 좌우 반전처럼 간단하지 않다. RGB 좌표계에서는
"이 색을 저 색으로 바꾸려면 어떤 값이어야 하는지"가 직관적이지 않기 때문이다.

**HSL 좌표계 (그림판 색 편집 메뉴에도 있다)**

| 성분 | 한글 | 의미 |
|---|---|---|
| **H** (Hue) | 색상 | 빨강/파랑 등 색 자체 |
| **S** (Saturation) | 채도 | 원색에 가까울수록 맑은 색, 회색에 가까울수록 탁한 색 |
| **L** (Lightness) | 명도 | 흰색에 가까울수록 밝고, 검은색에 가까울수록 어두움 |

**절차**
1. 이미지를 RGB → HSL로 변환
2. S, L을 1%씩 살짝 올리거나 내림 (H를 바꾸는 것은 semantic을 깨기 쉬우므로 보통 건드리지 않음)
3. 다시 RGB로 변환해 렌더링

RGB를 [0,1]로 normalize → max/min 찾기 → H, S, L 계산 → tweak → 역변환.

> 과제에서 이것저것 다양하게 조합해 성능을 올려보는 문제가 나올 예정.

## 2. Weight Initialization

### 2.1 0으로 초기화하면 안 되는 이유

미분해서 값을 넣어야 하는데 시작값이 전부 0이면 gradient가 0이 되어 업데이트가 안 된다.
→ **0이 아닌 값으로 시작**해야 한다. 그렇다면 무엇으로?

### 2.2 시도 1 — 작은 상수 × 정규분포

```python
W = 0.01 * np.random.randn(D_in, D_out)
```

평균 0, 작은 분산의 정규분포로 초기화. 그럴듯해 보인다.

**결과 (6층 네트워크, activation = tanh)**
- 첫 층은 분포가 그럴듯한데, 레이어를 통과할수록 activation이 **0으로 수렴**해버린다.

**이유**

$\tanh(Wx+b)$ 를 $W$ 에 대해 미분하면 $x$ 가 튀어나온다. tanh 출력은 $[-1, 1]$ 이므로,
1보다 작은 값이 입력되면 곱해질수록 점점 0 쪽으로 쏠린다. 층을 쌓을수록 이 효과가 누적되어
6층쯤 가면 거의 0 → **학습 불가**.

### 2.3 시도 2 — 큰 상수 × 정규분포

```python
W = 0.05 * np.random.randn(D_in, D_out)
```

**결과**
- 이번엔 값들이 $-1$ 과 $1$ 로 몰린다 (saturation).

**이유**

$\tanh$ 의 미분은 다음과 같다.
$$\frac{\partial}{\partial x}\tanh(Wx+b) = 1 - \tanh^{2}(Wx+b)$$
출력이 $\pm 1$ 이면 $\tanh^{2} = 1$ 이므로 미분값이 $1 - 1 = 0$. → **역시 학습 불가**.

> 상수가 너무 작으면 0으로 붕괴, 너무 크면 $\pm 1$ 로 포화. 적절한 중간값이 필요하다.

### 2.4 Xavier Initialization — 유도

**아이디어:** 임의의 상수를 곱하지 말고, **입력 차원 수의 제곱근으로 나눈다.**

```python
W = np.random.randn(D_in, D_out) / np.sqrt(D_in)
```

**Setup:** Fully-connected layer, 입력 $x \in \mathbb{R}^{D_{in}}$, 출력 $y \in \mathbb{R}^{D_{out}}$,
$W \in \mathbb{R}^{D_{in} \times D_{out}}$ (bias는 생략).
$$y_i = \sum_{j=1}^{D_{in}} w_{ij} x_j$$
**Step 1 — 분산 전개**
$$\mathrm{Var}(y_i) = \mathrm{Var}\left(\sum_{j} w_{ij} x_j\right)$$
**Step 2 — 독립 가정**

두 확률변수가 독립이면 분산을 따로 계산해 더할 수 있다.
$W$ 는 우리가 랜덤하게 초기화한 값이고 $x$ 는 데이터에서 오는 값이므로 엄밀히는 독립이 아니지만,
**학습 초기에는 $W$ 가 완전히 무작위이므로 러프하게 독립**이라고 볼 수 있다.
(학습이 진행될수록 $W$ 가 $x$ 와의 관계를 배우면서 점점 독립이 아니게 된다.)
$$\mathrm{Var}(y_i) = \sum_{j} \mathrm{Var}(w_{ij} x_j)$$
**Step 3 — 동일 분포 가정 (identically distributed)**

$w$ 는 정규분포로 초기화했고, $x$ 는 주어진 데이터의 분포다. 엄밀히는 같은 분포가 아니지만,
잘 모르니 일단 정규분포라 놓고 시작한다. Step 2와 묶어서 **IID assumption**.
$$\mathrm{Var}(y_i) = D_{in} \cdot \mathrm{Var}(w x)$$
**Step 4 — 분산의 정의**
$$\mathrm{Var}(wx) = E[w^{2}x^{2}] - \left(E[wx]\right)^{2} = E[w^{2}]E[x^{2}] - \left(E[w]\right)^{2}\left(E[x]\right)^{2}$$
**Step 5 — 평균 0 가정**

$E[w] = 0$: 정규분포 중심을 0으로 잡았으므로 성립.
$E[x] = 0$: 원본 이미지는 zero-mean이 아니지만, **data preprocessing에서 normalization을 하면** 성립.
$$\mathrm{Var}(wx) = E[w^{2}]E[x^{2}] = \mathrm{Var}(w)\,\mathrm{Var}(x)$$
**Step 6 — 결론**
$$\mathrm{Var}(y) = D_{in} \cdot \mathrm{Var}(w) \cdot \mathrm{Var}(x)$$
입력의 분산과 출력의 분산이 같아지려면 $D_{in} \cdot \mathrm{Var}(w) = 1$, 즉
$$\mathrm{Var}(w) = \frac{1}{D_{in}} \quad \Longrightarrow \quad \mathrm{std}(w) = \frac{1}{\sqrt{D_{in}}}$$
이렇게 하면 층을 쌓아 올라가도 입력 데이터의 분산이 출력에서도 거의 유지된다.

**한계:** 중간에 느슨한 가정들이 들어갔기 때문에 완벽하게 성립하지는 않는다.
실제로도 층을 지날수록 분포가 살짝씩 감쇠하지만, 앞의 두 시도보다는 훨씬 낫다.

### 2.5 Kaiming / MSRA Initialization (He init)

- ReLU도 똑같은 문제가 발생한다. 작게 시작하면 0으로 붕괴, 크게 시작하면 동일한 문제.
- 미분하면 $x$ 가 튀어나오는 구조는 동일하므로 원인도 같다.
- 유도 과정은 Xavier와 거의 같고, ReLU가 절반을 죽인다는 점을 반영해 스케일을 보정한다.
$$\mathrm{std}(w) = \sqrt{\frac{2}{D_{in}}}$$
ReLU가 입력의 절반을 0으로 만들기 때문에 분산이 절반으로 줄어드는 것을 분자의 2가 보상한다.

> **정리:** 이후로도 많은 연구가 나왔지만 초기화는 사실상 해결된 문제다.
> PyTorch 등에는 기본으로 들어가 있어서 그냥 불러다 쓰면 되지만,
> 밑바닥부터 짜려면 반드시 알아야 했던 문제였다.

## 3. Learning Rate Scheduling

### 3.1 왜 중요한가

> 굉장히 단순 무식한 작업인데, 이것 때문에 논문을 쓸 수 있는 걸 못 쓸 수도 있고
> 졸업을 할 수 있는데 못 할 수도 있다.

모델이 동작하지 않을 때 점검해야 할 순서:

1. **애초에 되는 문제인가?** input과 output 사이에 상관관계가 있는가?
2. **모델이 적절한가?** 상관관계가 있어도 모델이 맞지 않으면 못 찾는다.
3. **모델 크기가 적절한가?** 20층이 필요한 task에 3층 쓰고 포기하면 안 된다.
4. **데이터 양이 충분한가?**
5. **Learning rate가 맞는가?** ← 1~4가 다 맞아도 여기서 틀리면 학습이 안 된다.

### 3.2 Learning rate에 따른 loss curve

| LR | 증상 |
|---|---|
| **적절** | loss가 매끄럽게 잘 떨어짐 |
| **약간 큼** | 초반엔 잘 떨어지다가 optimal이 아닌 곳에서 수렴해버림 |
| **너무 큼** | 초반에 내려오다 확 발산 |
| **너무 작음** | 잘 안 떨어지고, 학습이 끝날 때까지 목표에 도달하지 못함 |

### 3.3 적절한 값은?

**"모른다"가 정답이다.** 데이터, 모델, 메모리에 따라 정해지는 batch size,
loss function이 노는 숫자의 스케일 등 여러 요소가 영향을 준다.

> 실제로 본 최댓값은 $10^{16}$, 최솟값은 $10^{-12}$ 수준까지도 있었다.
> "적절한 값의 범위" 같은 것은 존재하지 않는다.

**따라서 처음에는 넓은 범위에서 grid search.**
극단적인 값들은 대체로 잘 안 될 것이므로, 잘 되는 두 값 사이 구간에서 다시 세부적으로 탐색.

> 처음 하는 사람은 아이디어가 틀린 줄, 데이터가 부족한 줄, 모델이 잘못된 줄 알고 헤맨다.
> 경험 있는 사람이 "그거 learning rate 틀린 것 같은데" 한마디 해주면 풀리는 경우가 많다.

### 3.4 Learning Rate Decay

운이 좋으면 LR에 둔감한 문제라 $10^{-2}$ 든 $10^{-4}$ 든 비슷하게 나온다. 그런데 어떤 문제는
0.003은 잘 되는데 0.0029는 안 되는 식으로 극도로 민감하다.

이럴 때 general하게 쓸 수 있는 룰이 **decay**다.

**근거:** loss function은 보통 초반에 급격히 떨어지고 후반에 평평해진다.
- **초반**: 줄일 방향이 많으므로 LR을 크게 줘도 비교적 안전하다.
- **후반**: 평평한 곳에서 크게 뛰면 완전히 다른 곳으로 튈 수 있으므로 조심조심 가야 한다.

→ constant LR보다 **서서히 줄여 나가는 방식**이 더 많이 쓰이고 더 잘 된다.

**Step Decay (실제 Google에서 쓴 스케줄)**
- 전체 학습 시간의 **50%** 지점에서 LR을 $1/10$
- **75%** 지점에서 다시 $1/10$

관찰 결과:
- 50% 지점에서 수렴하는 듯하다가 LR을 낮추자 loss가 더 내려간다.
- 75% 지점에서는 효과가 더 미미하지만, 50% 지점은 확실히 유의미했다.
- **loss만 떨어진 게 아니라 실제 정확도도 올라갔다.**
- 즉 LR이 너무 높아 더 못 내려가고 헤매던 것을, 더 정교하게 내려가게 하니 얻는 것이 있었다.

> 몇 주 동안 더 세련된 방법들로 이 스케줄을 깨보려 했지만 못 이겼다.
> 모든 문제에서 항상 통용되는 것은 아니지만, 이렇게 하는 게 잘 되는 경우가 있다.

**Continuous Decay**
- Cosine, Linear, Inverse sqrt 등 함수를 정의해 step에 따라 연속적으로 LR을 줄이는 방식.
- 당연히 더 잘 될 것 같지만, 실제로는 꼭 그렇지도 않다. 실험해볼 것.

### 3.5 Warmup

초반 10% 정도는 아주 작은 값에서 시작해 **서서히 목표 LR까지 올린다.**

**이유:** 처음에는 무작위로 만들어놓은 loss 지형이 어떤 모습인지 전혀 모른다.
그 상태에서 갑자기 가장 큰 값으로 이리저리 뛰어다니게 하면 불안정해진다.
작게 시작해 지형을 어느 정도 파악한 뒤 크게 움직이자는 발상.

**전형적인 스케줄:** warmup → 목표 LR 유지 → $1/10$ → $1/10$

> **핵심: LR은 전반적으로 줄여 나가는 것이 보편적이다.**
> 늘려 나가는 경우는 (warmup 제외) 거의 없고, constant도 요즘은 잘 안 쓴다. Decay는 보통 한다.

## 4. Regularization

### 4.1 Overfitting이란

> 학습 데이터에 우연히 들어온 **노이즈까지 학습해버려서**, 일반적인 패턴이 아니라
> 그 데이터에만 있는 패턴까지 모델이 외워버리고, 새로운 데이터에서 일반화가 잘 안 되는 현상.

- 보통 **모델이 불필요하게 복잡할 때** 발생한다.
- 고차항의 계수들이 불필요하게 크게 들어가면서 노이즈까지 표현하게 된다.

**Deep Neural Network는 overfitting이 잘 될까?**
→ **엄청나게 잘 된다.** 파라미터가 많고 fully-connected 구조라
데이터가 정말 많지 않은 이상 배워야 할 패턴 대비 모델 크기가 커지기 너무 쉽다. 매우 flexible한 모델.

### 4.2 L2 / L1 Regularization (Weight Decay)

**기본 가정:** 고차항에 붙는 파라미터들은 실제로는 노이즈를 표현하는 데 쓰이는 값이다.
**계수가 커지는 것 자체가 그 항을 사용한다는 뜻**이므로, 커지는 것 자체에 페널티를 준다.
→ **"정말 필요하지 않으면 쓰지 마라"** 를 강제하는 것.

뉴럴 네트워크에서는 learnable parameter $W$ 하나하나가 그 계수에 해당한다.

| 이름 | Objective에 추가되는 항 | 대응 |
|---|---|---|
| **L2 (Weight Decay)** | $\lambda \sum_{k} W_{k}^{2}$ | Ridge Regression |
| **L1** | $\lambda \sum_{k} \lvert W_{k} \rvert$ | Lasso |

> 이름은 weight decay로 다르게 붙었지만 Ridge/Lasso의 L2/L1 regularization과 **완전히 같은 개념**이다.
> 실제로 잘 되고 많이 쓴다.

### 4.3 Early Stopping

**기본 가정:** *"신은 같은 실수를 반복하지 않는다."*
- 특정 training set에 우연히 들어간 노이즈는, 다른 샘플을 뽑으면 거기엔 없다.
- 반대로 **두 번 반복되면 그건 우연이 아니라 패턴**이다.

**방법**
1. 별도의 **validation set**을 만들어 성능을 체크.
2. Training set 성능은 계속 좋아지지만, validation loss가 **올라가기 시작하는 시점**이 온다.
3. 그 지점이 "노이즈를 배우기 시작하는 순간" → 거기서 멈춘다.

뉴럴 네트워크가 아니어도 모든 머신러닝 모델에서 쓸 수 있는 방법.

> ### ⚠️ 절대 test set으로 early stopping을 하면 안 된다
>
> 연구 세팅에서는 데이터가 다 주어져 있고 결국 그 스코어를 논문에 쓸 것이므로,
> **test set에서 제일 잘 나오는 시점에 멈추고 싶은 유혹**이 항상 생긴다.
>
> - **현실에서는 불가능하다.** 유튜브 추천 시스템을 런칭하면 test data는 "내일 접속할 사람"이다. 미래의 데이터를 미리 볼 수 없다.
> - 그렇게 멈추면 **test set에만 특화되어 잘 되는 시점**이 선택된다. 또 다른 overfitting이고, 더 나쁜 모델이 만들어진다.
> - 그걸 알면서도 했다면 **논문에 거짓말을 쓴 것**이다. 거기다 overfitting 시켜놓고 "이 스코어를 달성했다"고 쓰는 것은 양심이 찔리는 일.

### 4.4 Dropout

**아이디어:** fully-connected layer의 연결을 **일정 확률로 랜덤하게 끊어버린다.**
(Hinton 교수가 제안)

**왜 되는가 — "마스크 쓴 사람 알아보기" 비유**

마스크로 얼굴 상당 부분이 가려져 있어도 우리는 그 사람을 알아본다.
가려지지 않은 나머지 feature만 봐도 알 수 있을 만큼 여러 단서를 알고 있기 때문이다.

모델도 마찬가지로, 고양이임을 알기 위해 눈·귀·코·털 등 여러 곳에서 단서를 얻을 수 있다.
그런데 그중 **정말 확실한 단서 하나**가 보통 있고, 나머지는 약한 신호다.

> 모델은 사람처럼 **shortcut을 찾아간다.** "아, 귀만 보면 맞구나"를 귀신같이 배워서
> 거기에 weight를 몰아주고 나머지 단서는 잘 활용하지 않게 된다.

Dropout으로 귀 쪽에서 올라오는 신호를 끊어버리면, 모델은 죽이 되든 밥이 되든
**눈과 코를 보고** 맞춰야 한다. 틀리면 backprop이 눈·코에 해당하는 부분을 업데이트한다.
→ **평소 안 쓰던 부분을 강제로 보게 해서 여러 feature를 골고루 배우게 하는 방법.**

**구현 — Naive version**

```python
p = 0.5  # 살아남을 확률

def train_step(X):
    H1 = np.maximum(0, np.dot(W1, X) + b1)
    U1 = np.random.rand(*H1.shape) < p   # 0/1 mask
    H1 *= U1                             # 50% 확률로 0이 곱해져 사라짐

    H2 = np.maximum(0, np.dot(W2, H1) + b2)
    U2 = np.random.rand(*H2.shape) < p
    H2 *= U2

    out = np.dot(W3, H2) + b3

def predict(X):
    H1 = np.maximum(0, np.dot(W1, X) + b1) * p   # 스케일 보정
    H2 = np.maximum(0, np.dot(W2, H1) + b2) * p
    out = np.dot(W3, H2) + b3
```

**왜 test time에 $p$ 를 곱하는가 (스케일 문제)**

유닛이 10개인데 평균적으로 5개만 쓰였다면, dot product의 합 자체가 절반 스케일로 줄어든다.
그 스케일로 학습을 시켜놨는데 test time에는 dropout을 하지 않고 전부 쓰므로
**기댓값이 대략 2배**가 되어버린다 → 스케일이 안 맞음 → $p$ 를 곱해 보정.

**Inverted Dropout — 실제로 쓰는 방식**

위 방식의 문제: test time 코드가 학습 시 dropout 확률을 **기억하고 있어야** 모델을 쓸 수 있다.
모델을 여기저기 배포해서 편하게 쓰려면, **학습에 필요했던 것은 학습에서 끝내야 한다.**

→ 역으로 **학습 때 $p$ 로 나눠준다.**

```python
p = 0.5

def train_step(X):
    H1 = np.maximum(0, np.dot(W1, X) + b1)
    U1 = (np.random.rand(*H1.shape) < p) / p   # ← p로 나눔
    H1 *= U1

    H2 = np.maximum(0, np.dot(W2, H1) + b2)
    U2 = (np.random.rand(*H2.shape) < p) / p
    H2 *= U2

    out = np.dot(W3, H2) + b3

def predict(X):                                # test 코드는 손대지 않는다
    H1 = np.maximum(0, np.dot(W1, X) + b1)
    H2 = np.maximum(0, np.dot(W2, H1) + b2)
    out = np.dot(W3, H2) + b3
```

10개 중 5개만 살아남으면, 살아남은 애들에게 $1/0.5 = 2$ 를 곱해서
**"너는 두 배의 역할을 해야 한다"** 를 학습 단계에서부터 알려주는 것.
그러면 100% 기준 스케일로 학습이 이루어진다.

> 실제로는 PyTorch의 `nn.Dropout(p)` 를 쓰면 되고, 내부가 이렇게 되어 있다는 것만 이해하면 된다.

### 4.5 Regularization 정리

| 방법 | 비고 |
|---|---|
| **Dropout** | 보통 많이 씀. 특히 fully-connected layer일 때 |
| **Batch Norm / Layer Norm** | regularization 효과가 부수적으로 따라온다 |
| **Data Augmentation** | 데이터를 키우는 것이므로 **거의 무조건** 도움이 된다 |
| **L2 / L1 (Weight Decay)** | 잘 되고 많이 씀 |
| **Early Stopping** | 매우 중요. **최종 metric 기준으로 validation set에서 나빠지기 시작하는 시점** |

## 5. Batch Normalization

### 5.1 동기

Sigmoid 시절로 돌아가서: 절댓값이 큰 값이 나오면 gradient가 죽는다.
→ **"웬만하면 큰 값이 나오지 않게 하자."**

데이터는 주어진 대로 가는 것이지만, **적어도 학습할 때만이라도** 양 끝으로 가지 않고
가운데로 모이게 하면 gradient가 살아있는 구간에서 놀 수 있다.

**입력 레이어는 쉽다.** 데이터를 zero-centered, unit variance로 만들면 된다.
$$\hat{x} = \frac{x - \mu}{\sigma}$$
**문제는 중간 레이어.** 2층은 1층의 출력을, 3층은 2층의 출력을 받으므로 우리 마음대로 못 바꾼다.
2~3층까지는 별 문제가 아니었는데, 8층·15층·20층을 쌓고 싶어지면서 중간 레이어가 매우 중요해졌다.

→ **아이디어: 중간 레이어도 강제로 zero-mean, unit-variance로 바꿔버리자.**

### 5.2 왜 "Batch"인가

평균과 분산은 데이터 하나에서 정해지는 게 아니라 여러 데이터 포인트가 있어야 구할 수 있다.
- 입력 레이어는 전체 데이터셋에 대해 미리 계산할 수 있다.
- 하지만 중간 레이어 값은 **모델이 학습될 때마다 계속 달라지므로** 미리 계산할 수 없다.

→ **미니 배치로 들어오는 example들을 가지고 평균/분산을 구해서 normalize하자.**

### 5.3 수식

미니 배치가 $N$ 개, 각각 $D$ 차원일 때:

**Step 1 — 배치 평균 (D차원 벡터)**
$$\mu_j = \frac{1}{N}\sum_{i=1}^{N} x_{i,j}$$
**Step 2 — 배치 분산 (D차원 벡터)**
$$\sigma_j^{2} = \frac{1}{N}\sum_{i=1}^{N}\left(x_{i,j} - \mu_j\right)^{2}$$
같은 dimension 자리에 해당하는 example들끼리 평균을 낸다.

**Step 3 — Normalize ($N \times D$)**
$$\hat{x}_{i,j} = \frac{x_{i,j} - \mu_j}{\sqrt{\sigma_j^{2} + \varepsilon}}$$
**Step 4 — Scale & Shift ($N \times D$)**
$$y_{i,j} = \gamma_j \hat{x}_{i,j} + \beta_j$$
여기서 $\gamma$ 와 $\beta$ 는 학습되는 파라미터다.

### 5.4 왜 $\gamma$, $\beta$ 가 반드시 필요한가

Forward가 순차적으로 진행되고 있는데, 중간에서 우리가 마음대로
"너는 값이 너무 크니까 평균 빼서 줄여야 해"라고 강제 오퍼레이션을 넣고 있다.
당연히 학습이 제대로 안 된다.

→ **우리가 한 행동을 상쇄시켜줄 수 있는 반대 기능이 필요하다.**

- Normalize는 **activation function에 들어갈 때** zero-centered, unit-variance가 되게 하려는 것.
- 나온 다음에는 다시 **원상 복구**가 되어야 원래 스케일과 분산을 표현하면서 full capacity를 유지할 수 있다.
- $\gamma$ 가 분산의 역할, $\beta$ 가 평균의 역할.
- **중요: 이 값들은 고정된 상수가 아니라 학습된다.** 처음에 $\gamma=1, \beta=0$ 으로 두면
  identity이고, 학습하다 보면 "평균이 3만큼 빠지고 있으니 $\beta$ 가 3까지 올라가야겠다" 식으로 배운다.

### 5.5 Test time (Inference)

**Batch norm을 그대로 쓸 수 있을까? → 없다.**

- 애초에 학습할 때 gradient가 잘 흐르게 하려던 것이지, 테스트할 때는 그렇게 필요하지 않다.
- 게다가 **쓰고 싶어도 쓸 수 없다. 테스트에는 batch가 없다.**
  - 실험할 때 batch를 만드는 건 편의를 위한 것.
  - 실제 서비스를 생각해보자. 유튜브 추천 모델을 돌리는데 "batch size가 1000이니 1000명이 요청할 때까지 기다렸다가 추천을 띄우겠다"고 할 수 없다. 유저가 누르면 떠야 한다.
  - **서비스에서 test batch size는 무조건 1이다.**

**해결책: training 때 구해둔 값을 쓴다.**
- 학습 중 계속 계산해온 $\mu, \sigma$ 의 **running average (moving average)** 를 기억해두었다가
  test time에 그대로 넣는다.
- 이렇게 하면 학습된 $\gamma, \beta$ 와 거의 상쇄되어, 사실상 없는 것처럼 동작한다.

> **즉 test time의 batch norm은 그냥 "곱하고 더하는" 고정된 linear operator다.**

### 5.6 장점

- **학습을 쉽게 해준다** — gradient가 줄어드는 현상을 막고 중앙으로 모아준다 (gradient flow 개선)
- **더 높은 learning rate**를 써도 학습이 덜 깨지고 빠르게 수렴
- **초기화 값에 덜 민감**해진다
- **regularization 효과**도 약간 있다

→ 안 쓸 이유가 없는 방법으로 확 떴다.

### 5.7 단점

**(a) IID 가정이 필요하다**
- 배치 안의 example들이 IID여야 한다.
- 학습 중 시간순으로 분포가 점점 달라지면 평균/분산이 계속 달라져 의미가 없어진다.

**(b) Distribution Shift**
- Training 때 가정한 분포가 test 때도 유지되어야 학습해둔 $\mu, \sigma$ 를 쓰는 게 의미가 있다.

> **실제 사례 (Google):** 비디오 classifier를 만들어 유튜브에 런칭했다.
> 영상을 올리면 자동으로 돌아 태그를 달아주는 모델. **2년 동안 잘 썼다.**
> 그런데 어느 날 갑자기 "너희 모델에서 NaN이 나온다, 해결해봐"라는 알림이 왔다.
> 2년 전에는 없었던 어떤 영상의 현상이 지금 영상에는 들어 있다는 것 — **분포가 달라진 것.**
> 모델 어딘가를 찾아 고치는 건 사실상 불가능하고, **최신 데이터로 다시 학습**시켜야 한다.
> Distribution shift가 얼마나 있겠나 싶지만 실제로 존재한다.

**(c) 미니 배치 크기가 작으면 평균/분산이 제대로 안 구해진다**
- Batch size가 64, 128 정도면 괜찮지만, **비디오** 같은 걸 하면 batch size가 2, 심하면 1이다.
- 영상이 너무 크고 모델·backprop·데이터를 다 메모리에 올려야 하므로 하나씩밖에 못 올린다.
- 2~4개에서 구한 평균·분산은 매번 크게 달라진다 → 제대로 동작하지 않는다.

### 5.8 어디에 넣는가

**Linear layer 통과 후 → Activation function 들어가기 전**

activation에 들어가기 전에 zero-mean unit-variance로 만들어줘야
sigmoid든 ReLU든 중심(0) 근처로 들어가기 때문.

```
Linear → BatchNorm → Activation
```

PyTorch에 구현되어 있으므로 가져다 쓰면 된다.

## 6. Layer Normalization

### 6.1 동기

Batch에서 통계를 내는 게 싫다 (batch size 제약, IID 가정 등).
→ **다른 축에서 평균을 낼 수 없을까?**

여러 아이디어가 나왔다:
- **Layer Norm** — 같은 레이어 안의 값들끼리 평균
- **Batch + Layer 혼합**
- **Group Norm** — 그룹으로 묶어서 평균

> **결국 승자는 Layer Norm.** 다 비슷비슷하지만 지금 가장 많이 쓰이고 있다 (Transformer 등).

### 6.2 수식

$H$ = 해당 레이어의 hidden unit 개수. **하나의 example 안에서** 통계를 낸다.
$$\mu = \frac{1}{H}\sum_{k=1}^{H} a_k, \qquad
\sigma = \sqrt{\frac{1}{H}\sum_{k=1}^{H}\left(a_k - \mu\right)^{2}}$$

- 한 레이어 안의 유닛들끼리는 **같은** 평균/분산을 공유한다.
- Training example이 들어올 때마다 새로 계산하므로, 다른 example이 들어오면 다른 값을 쓴다.

**Batch Norm과의 차이**

| | 평균/분산을 내는 축 |
|---|---|
| **Batch Norm** | 같은 dimension에 대해, **여러 example에 걸쳐서** |
| **Layer Norm** | 하나의 example 안에서, **여러 노드에 걸쳐서** |

> 배치에 3개 example, 각각 6차원이라면 — Batch Norm은 세로로, Layer Norm은 가로로 통계를 낸다.
> **그것만 다르고 나머지는 다 똑같다.** ($\gamma, \beta$ 도 동일하게 학습, 효과도 비슷)

### 6.3 장점

- **미니 배치 크기와 무관하다.** Batch size가 1이어도 레이어 안에 값이 여러 개 있으므로 문제없다.
- 따라서 **inference 때도 그대로 쓸 수 있다.** $\mu, \sigma$ 를 기억할 필요가 없다.
- **Distribution shift를 걱정할 필요가 없다.** 각 example에 대해 그때그때 구해서 쓰므로 훨씬 깔끔하다.
- **RNN에서도 문제없다.** RNN은 시퀀스 길이가 서로 달라 batch 단위로 뭔가 하기가 어려운데, Layer Norm은 자기 안에서 계산하므로 문제가 생기지 않는다.
